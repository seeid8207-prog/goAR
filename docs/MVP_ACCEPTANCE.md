# GoAR MVP acceptance checklist

## Attendee
- [x] Ticket/seat destination is represented in the app.
- [x] Venue checkpoint QR can be scanned.
- [x] Persistent AR venue frame can be calibrated and stored.
- [x] Indoor graph route is calculated.
- [x] Active AR waypoints are rendered instead of every mapped point.
- [x] Live camera pose advances route progress.
- [x] Off-route movement triggers rerouting.
- [x] Lift/stair floor transitions are handled.
- [x] Step-free route preference is supported.
- [x] Arrival is detected.

## Venue mapping
- [x] Admin entry point exists.
- [x] AR mapper can save spatial seat points.
- [x] Mapped points persist locally.
- [x] A full numbered seat row can be generated from two endpoints.
- [x] Multiple rows can be generated by the shared seat-block generator.
- [x] Mapping can sync through the API adapter.

## Platform
- [x] Local offline venue package format exists.
- [x] Ticket-to-seat resolver exists.
- [x] Attendee/mapper/admin capabilities are separated.
- [x] Navigation telemetry events are defined.
- [x] Minimal persistent Node sync API is included.
- [x] Navigation/mapping core has CI tests.
- [x] EAS development/preview/production profiles are included.

## Physical validation still required before public deployment
- [ ] Test on supported ARCore Android device.
- [ ] Test on supported ARKit iPhone.
- [ ] Measure checkpoint calibration error in a real venue.
- [ ] Validate long-route AR drift and relocalization.
- [ ] Replace camera-ray placement with native plane/depth raycast where supported.
- [ ] Replace MVP JSON API storage with production database/object storage.
- [ ] Configure signing, store credentials, privacy policy and production API URL.
